Controls: pick a framework (built-in subset catalogs for NIST 800-53 r5, CSF 2.0 and an AI-governance set, or a full catalog imported as OSCAL JSON), per-control status (satisfied / partly / not satisfied / no usable evidence / not observed by Quanta), tests, Attest, OSCAL assessment-results download. /api-securityAPI Security (admin)API inventory, OWASP API Top 10 findings, caller activity, data classes, protection policiesTabs Overview, Inventory, Import, Findings, Callers, Data classes, Protection policies, Metrics, CI and rollout. Overview: endpoints, services, shadow endpoints, endpoints open without credentials, critical-or-high findings, gaps, specifications, service dependencies, onboarding progress. Inventory: filter by service, state (documented / shadow / no spec for service / documented-not-seen), exposure and authentication; per endpoint the data it returns under your classes, owner, calls, findings, and a detail view with evidence, daily metrics and callers. /dark-web-watchDark Web Watch (admin)Leak-site feeds, credential-exposure lookups and imported crawler output matched against your namesTabs Hits, Sources, Watch terms, Import. /socSOC Operations (admin)Cases in L1, L2 and L3 queues; metrics; log and technique analysisTabs Queues, Metrics, Logs and techniques, Analysts. Queues: open cases in three columns with priority (impact x urgency), status, owner and service-level state; open a case; a case page shows the summary (the analyst's, or one generated from the facts), linked alerts, techniques, actions (take, assign, note, mark waiting, escalate with a hand-off summary, resolve with a code and summary, close, reopen), pasted-log analysis and the full history. Metrics: alert-to-action timing (to first investigation, to a case, to a person acknowledging, share investigated automatically), MTTA, MTTR (mean, median, p90), service-level compliance per clock, backlog, escalation and reopen rates, false-positive rate, recommendation accuracy, automation rate, analyst workload, per-day series. Logs and techniques: Naive Bayes technique identification and log statistics (bursts, regular-interval connections, failures then success, indicators). Analysts: who works which tier. Quanta records and measures the work; it never changes your systems.
/huntingHunting & SOC (admin)Hunts proposed from live exposure; alert triage with vulnerability contextTabs Overview, Proposed hunts, Hunts, Alert triage. Overview: hunts proposed, closed, confirmed, alerts open, ATT&CK hunt coverage of the techniques in open findings. Proposed hunts: one per open CVE that is on the KEV list or has EPSS 0.5 or higher, with hypothesis, hosts, tagged techniques, ready-made queries (Splunk SPL), Start this hunt. Hunts: status, outcome (confirmed / not-found / needs-data; closing needs one), per-query result recorded by the analyst, notes, follow-ups, detection created. Alert triage: alerts received through POST /api/ingest/alerts (soc:write key) ranked by priority with reasons, host owner, open and KEV findings, a runbook, and status / disposition / assignee / notes. Each new alert is investigated on arrival (locally); the alert page shows the structured report (history, entities with privileged-access detail, ATT&CK, attack flow, indicators, blast radius, what your tools did, recommended actions with suggested playbooks, references), follow-up questions merged into the report, and a look-back field (past 90 days needs a written reason). A hunt opens with summary figures (leads run, with results, entities, techniques with no rule) and Run all leads (preview, cap, look-back reason). Quanta is not a SIEM and runs no queries; the analyst runs them in their own tool
