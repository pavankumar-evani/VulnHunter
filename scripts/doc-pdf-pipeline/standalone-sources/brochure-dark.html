The problem

Finding vulnerabilities and fixing them are two different jobs

Every scanner produces a report. Almost none of them produce a fix — the harder half of the job lands on whoever picks up the ticket, using data from sources that don't agree with each other.

Reports nobody finishes reading

Static analysis and scanners are good at finding — the report is where most tools stop. Turning “here's what's wrong” into a safe, reviewable change is almost entirely manual.

Incompatible sources, incompatible assets

CVE/CVSS host findings from Tenable-class scanners, device-risk findings for what agents can't reach, manual threat intel — landing on assets as different as domain controllers and firewalls.

“We have vulnerabilities detected from Tenable, manual threat intel, and Armis, and we have to remediate them across Windows servers, end-user devices, Unix servers, network routing/switching, and network security devices — instead of manual remediation effort, is there an AI-based remediation solution that can help?”

The solution

One differentiator: a generated fix, not another ticket

VulnHunter closes the loop — scan, triage, fix, and (for code) a real pull request — with a human decision point at every step that touches real infrastructure. Every source normalizes into one schema; every CVE-scoped finding is checked against live exploitation data; every eligible finding gets a real, reviewable fix artifact.

Not a marketing claim — a verified market gap

ServiceNow's own current Vulnerability Response/USEM documentation describes remediation as a phased task process: import, triage, and monitor progress to completion — workflow automation, not fix-artifact generation. Tenable, Qualys, and Rapid7 don't generate fixes either; they're scanners that feed a ticketing system like ServiceNow.

Capabilities

What's actually inside

Live threat-intel prioritization

Real CISA KEV and FIRST.org EPSS enrichment — an actively-exploited CVE is force-escalated regardless of asset type; a high-EPSS CVE with no KEV listing yet is caught before it becomes one.

Four remediation tracks

IT infrastructure (generated Ansible playbooks), Application Security (a real git branch + PR for mechanical code fixes), OT/IoT (a compensating-control recommendation — never an automated patch, per NIST SP 800-82), and SCA dependency upgrades — each shaped for how that category is actually fixed in practice.

Risk correlation, not just severity

Attack-chain grouping (entry → pivot → impact by MITRE ATT&CK tactic), SBOM-derived dependency blast radius, and real compensating-control coverage scoring from your own firewall/EDR posture.

Governed AI, not an autonomous agent

AI Assist and AI Trend Analysis explain and draft — they never execute. Every subagent that touches infrastructure holds Read/Write tools only, by construction, not by policy.

Governance built in, not bolted on

  • Role + team-scoped access control, with every mutating action gated server-side.
  • A real approval workflow — Approve / Reject / Trigger — separate from time-boxed risk-acceptance exceptions.
  • A live audit trail with anomaly detection on unusual actor or action volume.
  • 8 live pull connectors and 3 push connectors (ServiceNow, Jira, Splunk), each with a disclosed, honest verification status.
